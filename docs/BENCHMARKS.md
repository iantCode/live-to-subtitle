# 측정 기록

Live to Subtitle 의 지연 시간과 번역 정확도를 측정한 방법과 결과입니다. 설정을 바꿀지 판단할 때 참고하세요.
모든 측정은 RTX 5080 한 대에서 했습니다.

## 측정 방법

**정확도.** 한 중국 게임의 공식 한국어 채널은 개발자 라이브 방송 다시보기에 사람이 만든 한국어 자막을 붙여 올립니다.
중국어 음성을 실제 재생 속도로 프로그램에 넣고, 30초 구간마다 프로그램의 자막과 공식 자막의 **의미가 얼마나 같은지**를
상위 모델(gpt-6.2-sol)이 100점 만점으로 채점합니다. 두 설정을 비교할 때는 같은 구간을 순서를 섞어 한 번에 채점하고,
글자 겹침 지표(chrF)도 함께 봅니다. 같은 설정을 두 번 돌려도 평균이 1~2점 달라지므로, 그보다 작은 차이는 같다고 봅니다.

- 영상 1: 새 버전 소개 라이브 방송 (82분, 게임 시스템 설명 위주). 앞 12분으로 채점
- 영상 2: 개발자 라디오 방송 (92분, 스토리·음악 이야기). 5~20분은 용어를 찾는 데 쓰고, 35~45분과 60~72분은 확인용

**번역만 비교할 때**는 한 번 인식한 중국어를 설정만 바꿔 다시 번역합니다 (인식의 흔들림을 빼기 위해).

## 지연 시간

실제 중국어 라이브 방송 실시간 재생.

| 구간 (중앙 / p90) | 최초 버전 | 말 멈춤 감지 + 번역 재사용 후 |
|---|---|---|
| 말 끝 → 중국어 문장 확정 | 1.48 / 2.69초 | 1.18 / 2.66초 |
| 확정 → 한국어 번역 | 0.86 / 1.12초 | 0.72 / 1.05초 |
| **말 끝 → 번역 완료** | **2.43 / 3.67초** | **1.80 / 3.49초** |

- 번역 시간의 대부분(약 0.7~0.9초)은 OpenAI 서버의 첫 응답 대기입니다.
  연결 설정(keepalive 연장, `service_tier=priority`)은 차이가 없었습니다.
- `silence_commit_sec` / `step_sec` 를 줄여도 0.1초 이하로만 빨라지고 너무 짧은 줄이 생겼습니다.

**장시간 실행** (영상 1 전체 82분, 실시간): 1,788줄, 번역 요청 4,147회, 최종 번역 누락 0, 오류 0.
메모리는 약 800MB 에서 늘지 않았고, 말 끝 → 번역 중앙값은 20분 구간마다 2.23~2.40초로 일정했습니다.

## 방송 지연과 자막 표시

자막을 '말 시작 + 지연' 에 띄울 때, 말하는 동안 그 말의 자막이 화면에 떠 있는 비율.
필요한 지연은 '말하는 시간 + 확정(약 1.2초) + 번역(약 1초)' 이라, 자막 한 줄이 길수록 길어집니다.

영상 2 60~72분, 확정 번역만 표시:

| 줄 길이 (`soft_max_chars` / `max_chars` / `max_sec`) | 6초 | 7초 | 8초 | 10초 | 정확도 |
|---|---|---|---|---|---|
| 18 / 30 / 9.0 | 75% | 84% | 89% | 93% | 기준 |
| 15 / 24 / 6.0 | 88% | 95% | 96% | 98% | 1~4점 낮음 |
| 12 / 20 / 5.0 | 92% | 99% | 99.9% | 100% | 3~5점 낮음 |
| 18 / 30 / 9.0 + 다시 번역 (현재 기본) | | | 97% | **99%** | **+4점** |

(다시 번역을 켠 실행은 다른 시간대에 측정해 번역 속도가 조금 빨랐습니다.)

## 번역 정확도: 시험한 방법

영상 2 60~72분, 같은 중국어를 다시 번역해 비교한 의미 점수 변화.

| 방법 | 변화 | 비고 |
|---|---|---|
| 같은 설정 한 번 더 (흔들림 확인) | +1.4 ~ +1.9 | 이 정도 차이는 같은 것으로 봄 |
| **다음 1줄을 참고해 번역** | **+5.7** | 18 / 24 구간 우세. 현재 기본 (`refine`) |
| 다음 2줄 참고 | +5.7 | 1줄과 같음 |
| 추론 강도 low | +1 ~ +5 | 측정마다 들쭉날쭉 |
| 앞 문맥 8줄 (기본 4줄) | +2 ~ +3 | |
| 짧은 줄 (12 / 20 / 5.0) | −3 ~ −5 | 문장이 잘려 번역됨. 앞 문맥을 늘려도 회복 안 됨 |
| gpt-6.1-terra | +10.9 | chrF 도 상승. 요금이 비쌈 |
| gpt-6.2-astra (low) | +11.5 | 더 느리고 chrF 는 하락 |
| Whisper large-v3 (인식) | −1.2 | 더 느리기만 함 |

**다시 번역(refine)을 실제로 돌린 결과** (방송 지연 10초, 실시간): 78% 의 줄에서 마감 전에 끝났고(평균 0.9초 여유),
같은 실행의 첫 번역보다 +3.8점 (24구간 중 18구간 우세). 다음 줄이 '확정' 되기를 기다리면 긴 줄에서는 제때 오는 비율이
약 60% 라서, 아직 인식 중인 말까지 참고합니다.

**모델 비교** (실시간, 세 설정 동시 실행이라 절대 지연은 평소보다 큼):

| 설정 | 의미 점수 | 말 끝 → 번역 (중앙 / p90) |
|---|---|---|
| luna | 72 | 2.80 / 3.97초 |
| terra | 80 | 3.12 / 4.76초 |
| terra + 임시 번역은 luna | 80 | 3.13 / 4.52초 |

**임시 번역(draft)을 끈 경우**: API 호출이 514회에서 238회로 줄었고, 확정 번역은 같거나 조금 빨랐습니다 (2.76초 대 3.01초).
오버레이가 확정 번역만 보여 주므로 기본으로 끕니다.

## 용어집 효과 (그 게임의 용어집 사용)

**영상 1 (앞 12분)**

| 설정 | 의미 점수 |
|---|---|
| 시스템 용어 10개 + 고유명사 용어집 | 64.9 |
| + 전투 용어·진행자 별명·신캐릭터 (병음 포함) | **73.7** |

전투 시스템을 설명하는 구간은 약 55점에서 약 83점으로 올랐습니다.

**영상 2** (괄호는 같은 회차의 이전 점수)

| 설정 | 5~20분 (용어 찾는 데 사용) | 35~45분 (확인용) |
|---|---|---|
| 교정표 + 핵심 용어 | 76.3 (72.7) | 67.5 (63.1) |
| + 게임 화면 용어 + 발음 힌트 | **77.4** (72.4) | **67.9** (63.5) |
| 위에서 교정표만 뺌 | 75.4 (71.9) | 68.5 (64.7) |

교정표 없이 발음 힌트만으로도 거의 같은 효과가 납니다.

2음절 캐릭터 이름 발음 힌트 + 이번 버전 스토리 용어 추가: 60~72분(처음 사용) 70.1 → **74.4**.
가장 큰 오류였던 주요 캐릭터 이름(발음이 같은 다른 글자로 인식되어 엉뚱한 이름으로 번역)이 14줄 중 13줄 바르게 바뀌었습니다.

**시도했다가 뺀 것**
- Whisper `hotwords` (인식 단계에 용어를 미리 알려 줌): 쉼표가 줄어 문장이 덜 잘리고, 용어 목록을 그대로 받아 적는 환각이 늘었습니다.
- 발음 힌트를 번역할 줄 바로 옆에 두기: 반영률이 63/70 → 64/70 으로 같았고, 틀린 힌트도 더 잘 따라갔습니다.

**남은 오류**는 대부분 게임과 무관한 일반 문장의 인식 오류(`服从性测试` → `浮沉测试`), 비유·문화 표현,
노래·앨범 이름 같은 게임 밖 고유명사입니다.
